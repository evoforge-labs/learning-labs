Hãy tưởng tượng bạn đang chấm điểm thi cho cả lớp. GROUP BY giống như gộp tất cả học sinh lại thành một dòng "điểm trung bình lớp". Window functions giống như xếp hạng từng học sinh *trong khi vẫn giữ nguyên thông tin của từng người*. Bạn vừa có bảng đầy đủ, vừa biết ai đứng thứ mấy.

## Là gì

**Window functions** tính toán trên một "cửa sổ" (window) các hàng liên quan đến hàng hiện tại — mà *không gộp* chúng thành một hàng duy nhất.

Sự khác biệt cốt lõi so với GROUP BY:
- GROUP BY: 10 hàng → 3 hàng (mỗi nhóm 1 hàng)
- Window function: 10 hàng → vẫn 10 hàng, nhưng mỗi hàng có thêm cột tính toán

Cú pháp cơ bản:

```sql
hàm_tính_toán() OVER (
  PARTITION BY cột_nhóm
  ORDER BY cột_sắp_xếp
)
```

- `PARTITION BY` — chia dữ liệu thành các nhóm độc lập (như GROUP BY nhưng không gộp)
- `ORDER BY` bên trong OVER — xác định thứ tự trong mỗi nhóm

## Ví dụ thật

Bảng `events`:

| user_id | event_name | created_at          |
|---------|------------|---------------------|
| 101     | signup     | 2024-01-10 08:00    |
| 101     | activated  | 2024-01-10 09:30    |
| 101     | purchase   | 2024-01-12 14:00    |
| 102     | signup     | 2024-01-11 10:00    |
| 102     | purchase   | 2024-01-13 16:00    |

**Tìm event đầu tiên của mỗi user (first event per user):**

```sql
SELECT *
FROM (
  SELECT
    user_id,
    event_name,
    created_at,
    ROW_NUMBER() OVER (
      PARTITION BY user_id
      ORDER BY created_at ASC
    ) AS thu_tu
  FROM events
) t
WHERE thu_tu = 1;
```

`ROW_NUMBER()` đánh số thứ tự từ 1 trong mỗi nhóm `user_id`, sắp xếp theo `created_at`. Lấy hàng số 1 là lấy event sớm nhất. Không cần subquery phức tạp, không cần self-join.

**Running total — tổng lũy kế số event theo ngày:**

```sql
SELECT
  DATE(created_at) AS ngay,
  COUNT(*) AS event_ngay_do,
  SUM(COUNT(*)) OVER (
    ORDER BY DATE(created_at)
  ) AS tong_luy_ke
FROM events
GROUP BY DATE(created_at)
ORDER BY ngay;
```

Cột `tong_luy_ke` cộng dồn từng ngày — hữu ích để vẽ đường tăng trưởng tích lũy.

**Xếp hạng user theo số lượng purchase:**

```sql
SELECT
  user_id,
  COUNT(*) AS so_purchase,
  RANK() OVER (ORDER BY COUNT(*) DESC) AS hang
FROM events
WHERE event_name = 'purchase'
GROUP BY user_id;
```

<Callout title="Cẩn thận">
`ROW_NUMBER()` luôn cho số thứ tự liên tục (1, 2, 3...). `RANK()` cho cùng số nếu bằng điểm rồi nhảy (1, 2, 2, 4). `DENSE_RANK()` cho cùng số nếu bằng điểm nhưng không nhảy (1, 2, 2, 3). Chọn sai loại có thể dẫn đến kết quả không như mong đợi — đặc biệt khi dùng để lọc top N.
</Callout>

Window functions thường chạy chậm hơn GROUP BY trên bảng lớn. Nếu chỉ cần tổng hợp đơn giản, dùng GROUP BY. Dùng window functions khi bạn cần giữ chi tiết từng hàng *đồng thời* có phép tính theo nhóm.

<Callout title="Nhớ nhé">
Window functions = tính toán theo nhóm mà không mất chi tiết từng hàng. Ba use case phổ biến nhất: (1) tìm first/last event per user với ROW_NUMBER, (2) running total với SUM OVER, (3) xếp hạng với RANK. Tất cả dùng cú pháp `hàm() OVER (PARTITION BY ... ORDER BY ...)`.
</Callout>
