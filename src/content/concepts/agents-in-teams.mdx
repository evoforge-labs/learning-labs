Hãy nghĩ đến một nhân viên mới vào team. Bạn không muốn giải thích lại từ đầu mỗi ngày: "code style của mình là thế này, test chạy lệnh này, branch đặt tên theo kiểu kia." Bạn viết một tài liệu onboarding một lần, ai cũng đọc. Agent hoạt động theo đúng nguyên tắc đó.

## Là gì

**Agents in Teams** là bộ quy ước và chuẩn chung để nhiều người trong một team có thể dùng agent AI (như Claude Code) theo cách nhất quán — cùng style, cùng quy trình, cùng hiểu codebase.

Công cụ trung tâm là **CLAUDE.md** (hoặc AGENTS.md — tên file tương đương được hơn 15 coding agent chính thức đọc vào năm 2026). Đây không phải README thông thường. Đây là **tài liệu onboarding cho agent**: agent đọc nó khi bắt đầu mỗi session, không phải người.

File này thường chứa:

- Lệnh build/test/lint cụ thể của project
- Quy tắc code style không tự suy được từ code
- Quy ước đặt tên branch, PR, commit
- Các gotcha và quirk đặc thù của repo
- Paths quan trọng và kiến trúc cấp cao

Độ dài lý tưởng: **200–500 dòng**. Quá dài, agent bỏ qua những phần quan trọng vì bị "chôn vùi". Quá ngắn, agent phải đoán và thường đoán sai.

## Ví dụ thật

**Monorepo với nhiều package**: Team dùng cấu trúc phân tầng —

- `CLAUDE.md` ở root: quy tắc chung toàn repo (commit convention, CI, shared tooling)
- `packages/api/CLAUDE.md`: quy tắc riêng cho service API (framework, auth pattern, migration workflow)
- `packages/web/CLAUDE.md`: quy tắc riêng cho frontend (component naming, styling, state management)

Khi agent làm việc trong `packages/api/`, nó tự động nạp cả root và sub-CLAUDE.md — không cần bạn chỉ định.

**Khởi động từ đầu**: Chạy `/init` trong Claude Code để agent tự phân tích codebase và sinh bản nháp CLAUDE.md. Bạn review, cắt bỏ những gì agent đã tự biết, giữ lại những gì thật sự cần nhắc.

Hãy kiểm tra định kỳ: nếu agent hay hỏi những câu mà CLAUDE.md đã trả lời, tức là cách diễn đạt chưa rõ. Nếu agent làm đúng mà không cần nhắc, hãy xóa dòng đó để file gọn hơn.

<Callout title="Nhớ nhé">
CLAUDE.md là "source of truth" của team — check vào git để mọi người (và mọi agent) đọc cùng một phiên bản. Treat nó như code: review khi có PR, cập nhật khi convention thay đổi, và cắt bỏ những gì thừa.
</Callout>
