Bạn thuê thợ sơn nhà. Thợ giỏi sẽ nhìn khắp phòng, hỏi vài câu, rồi nói: "Tôi cần 3 lít sơn màu này, trét tường chỗ kia trước, che đồ đạc lại." Thợ vội sẽ mở sơn ra và bắt đầu quét ngay. Cái nào ít tốn tiền sơn thêm và ít đau đầu hơn?

Đó là lý do Plan Mode tồn tại trong Claude Code.

## Là gì

**Plan Mode** (hay plan-then-execute) là chế độ mà agent chỉ được phép *đọc* — không sửa file, không chạy lệnh phá hoại — cho đến khi bạn xem và duyệt kế hoạch của nó.

Claude khám phá codebase, đặt câu hỏi, rồi viết ra một kế hoạch cụ thể: sẽ sửa file nào, theo thứ tự nào, lý do là gì. Bạn đọc kế hoạch đó, chỉnh sửa nếu cần (nhấn `Ctrl+G` để mở trong editor), rồi mới cho phép Claude bắt tay vào code.

Quy trình 4 pha chuẩn:

1. **Explore** — Claude đọc file, tìm hiểu kiến trúc (plan mode)
2. **Plan** — Claude đề xuất kế hoạch chi tiết (plan mode)
3. **Implement** — Claude sửa code theo kế hoạch (thoát plan mode)
4. **Commit** — Claude commit với message mô tả rõ ràng

Để bật plan mode: `claude --permission-mode plan`. Hoặc nhấn `Shift+Tab` để chuyển qua lại giữa các mode. Muốn mặc định luôn bắt đầu bằng plan mode, thêm vào `.claude/settings.json`:

```json
{
  "permissions": {
    "defaultMode": "plan"
  }
}
```

## Ví dụ thật

Bạn cần thêm Google OAuth vào app. Thay vì nói "thêm Google OAuth đi", bạn vào plan mode và hỏi: "Đọc `/src/auth` và hiểu cách chúng ta xử lý session. Tôi muốn thêm Google OAuth — cần sửa những file nào?"

Claude đọc toàn bộ flow xác thực, rồi viết ra: "Cần sửa 4 file: `auth.ts`, `routes/oauth.ts`, `db/schema.ts`, và `CLAUDE.md`. Thứ tự: schema trước để có bảng users mới, rồi route callback, rồi middleware..."

Bạn đọc, thấy Claude quên mất file `.env.example`, thêm vào kế hoạch, rồi mới gõ "thực hiện". Claude triển khai đúng kế hoạch đã được duyệt — không có bất ngờ.

<Callout title="Cẩn thận">
Plan mode hữu ích nhất khi bạn chưa chắc về cách tiếp cận, hoặc thay đổi ảnh hưởng nhiều file. Với task nhỏ rõ ràng — sửa một typo, đổi tên biến — plan mode chỉ thêm overhead không cần thiết. Biết khi nào nên bỏ qua plan cũng là kỹ năng quan trọng.
</Callout>

<Callout title="Nhớ nhé">
Kế hoạch không phải bản thiết kế cứng nhắc — đó là "hợp đồng sống". Bạn có thể chỉnh sửa nó trước khi duyệt, và Claude sẽ follow kế hoạch đã được duyệt, không phải kế hoạch ban đầu của nó.
</Callout>
