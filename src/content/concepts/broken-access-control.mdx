Khách sạn cấp cho bạn chìa khóa phòng 101. Bạn tò mò thử chìa đó vào phòng 102 — và cửa mở. Không cần hack gì cả. Chỉ cần thử.

Đó là Broken Access Control: **hệ thống không kiểm tra đúng xem người dùng có thực sự được phép làm điều họ đang cố làm không**.

## Là gì

**Broken Access Control** là khi ứng dụng không thực thi đúng các giới hạn quyền hạn — để người dùng truy cập, chỉnh sửa, hoặc xóa tài nguyên thuộc về người khác, hoặc thực hiện chức năng vượt quyền của họ.

Đây là lỗ hổng **#1 trong OWASP Top 10:2025** vì cực kỳ phổ biến và dễ khai thác.

Biến thể phổ biến nhất là **IDOR (Insecure Direct Object Reference)**: ứng dụng dùng ID từ URL/request để truy vấn database mà không kiểm tra quyền sở hữu.

## Ví dụ thật

Bạn đăng nhập và xem hóa đơn của mình tại:

```
GET /api/invoices/1042
```

Bạn đổi `1042` thành `1041` — và nhận được hóa đơn của người khác. Server trả về dữ liệu mà không hỏi "người đang gọi API này có quyền xem hóa đơn 1041 không?"

Code bị lỗi:

```python
# NGUY HIỂM — chỉ lấy invoice theo id, không kiểm tra chủ sở hữu
@app.get("/api/invoices/{invoice_id}")
def get_invoice(invoice_id: int):
    return db.query(Invoice).filter(Invoice.id == invoice_id).first()
```

Code đúng:

```python
# AN TOÀN — luôn lọc theo cả id lẫn user đang đăng nhập
@app.get("/api/invoices/{invoice_id}")
def get_invoice(invoice_id: int, current_user = Depends(get_current_user)):
    invoice = db.query(Invoice).filter(
        Invoice.id == invoice_id,
        Invoice.owner_id == current_user.id  # kiểm tra quyền sở hữu
    ).first()
    if not invoice:
        raise HTTPException(status_code=404)
    return invoice
```

Ngoài IDOR, Broken Access Control còn bao gồm: truy cập trang admin khi không phải admin (vì server chỉ kiểm tra ở frontend), leo thang quyền (privilege escalation), hay truy cập endpoint theo phương thức HTTP khác không được bảo vệ.

<Callout title="Cẩn thận">
Dùng UUID thay vì số nguyên (`invoice_id = 1042` vs `invoice_id = uuid`) không giải quyết được IDOR — chỉ làm khó đoán hơn. Kẻ tấn công có thể lấy UUID từ nguồn khác. Kiểm tra quyền ở server mới là cách duy nhất đúng.
</Callout>

<Callout title="Nhớ nhé">
Kiểm tra quyền phải ở **server**, không phải ở frontend. Mọi API endpoint chạm vào dữ liệu đều cần hỏi: "Người đang gọi endpoint này có được phép truy cập tài nguyên *cụ thể này* không?" — không chỉ "người này đã đăng nhập chưa?"
</Callout>
