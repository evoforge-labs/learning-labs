Một API key bị commit lên GitHub public repo trung bình bị tìm thấy trong vòng 30 giây bởi bot quét tự động. Không phải 30 phút. 30 giây.

Đó là lý do tách config khỏi code không phải "best practice" tùy chọn — đó là điều kiện tối thiểu để ship an toàn.

## Là gì

**Config** là mọi thứ có thể thay đổi giữa các môi trường: database URL, port, feature flag, tên bucket S3. Không nhạy cảm nếu lộ, nhưng cần khác nhau giữa dev/staging/prod.

**Secrets** là config nhạy cảm: API key, database password, private key, OAuth client secret. Lộ secret = mất tiền, mất dữ liệu, mất tin tưởng của user.

Nguyên tắc nền tảng: **không cái nào trong hai loại trên nên nằm trong code.**

## Ví dụ thật

**Cách sai:**
```python
STRIPE_SECRET_KEY = "sk_live_abc123xyz..."
DATABASE_URL = "postgresql://admin:password@prod-db.example.com/app"
```

Commit file này lên Git → lộ credentials → ai clone repo đều có thể charge thẻ của user bạn.

**Cách đúng — local development:**

Tạo file `.env` (không commit):
```
STRIPE_SECRET_KEY=sk_live_abc123xyz...
DATABASE_URL=postgresql://...
```

Thêm `.env` vào `.gitignore`. Trong code đọc từ env:
```python
import os
stripe_key = os.environ["STRIPE_SECRET_KEY"]
```

**Trên production**, không dùng file `.env`. Inject trực tiếp qua platform: Railway, Fly.io, Render, Vercel đều có UI để set environment variables. Giá trị được mã hóa, không bao giờ xuất hiện trong code hay logs.

**Khi cần quản lý nhiều secrets hoặc chia sẻ trong team**, dùng secret manager: Doppler, AWS Secrets Manager, hoặc HashiCorp Vault. Secrets được lưu tập trung, có audit log, và được inject vào app lúc runtime — không cần file `.env` trên bất kỳ server nào.

<Callout title="Cẩn thận">
`.env` an toàn cho local development, nhưng **không phải giải pháp cho production**. File `.env` trên server là rủi ro: nó có thể bị sao lưu nhầm, được đọc bởi process khác, hay bị leak qua error log. Trên production, hãy để platform inject secrets trực tiếp vào environment của process.
</Callout>

**Checklist tối thiểu cho mọi project:**

1. `.env` có trong `.gitignore` chưa? Kiểm tra ngay bây giờ.
2. Có file `.env.example` (không có giá trị thật) để dev mới biết cần set gì không?
3. Trên production, secrets được set qua platform UI hay CI/CD chưa — không phải file?
4. Đã scan repo xem có commit nhầm secret nào chưa? Dùng `git log -p | grep -i "sk_live\|password\|secret"`.

<Callout title="Nhớ nhé">
Commit secret lên Git là lỗi không thể hoàn tác hoàn toàn — kể cả khi bạn xóa commit sau đó, secret đã bị index bởi bot. Khi phát hiện lộ secret: **rotate ngay lập tức** (tạo key mới, vô hiệu hóa key cũ), rồi mới lo dọn dẹp Git history.
</Callout>
