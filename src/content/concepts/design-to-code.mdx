Bạn có bản thiết kế đẹp trên Figma. Rồi bạn ngồi code lại — từng pixel, từng màu, từng khoảng cách — nhìn đi nhìn lại so sánh. Một giờ sau, nó ra được 70%. Hai giờ nữa để "kéo" nốt 30% còn lại. Và hôm sau designer nói cần sửa nút ở 3 chỗ.

Cái vòng lặp đau đớn đó gọi là "pixel pushing". Và nó không cần thiết.

## Là gì

**Design to code** là quá trình biến thiết kế trực quan thành giao diện chạy được trong code. Làm đúng, bước này không phải "copy từng pixel" — mà là áp dụng **design token + component có sẵn** để implement nhanh và giữ nhất quán.

Ba cách tiếp cận thực tế:

1. **Dùng component library (shadcn/ui, Radix, Chakra):** Bạn không vẽ lại nút, card, input — bạn lấy component có sẵn và chỉnh token/props. Nhanh hơn gấp 3-5 lần so với làm từ đầu.
2. **Tailwind CSS với token:** Thay vì viết CSS tùy ý, bạn map design token sang Tailwind utilities. `bg-primary`, `p-4`, `rounded-lg` — nhất quán với config, không hardcode.
3. **AI-assisted:** Dùng AI (Cursor, Claude Code, v0.dev) để generate component từ mô tả hoặc screenshot. Vẫn cần bạn review và điều chỉnh token, nhưng boilerplate xong trong giây.

## Ví dụ thật

Bạn cần implement một card sản phẩm: ảnh, tên, giá, nút "Thêm vào giỏ". Thay vì tự CSS từ đầu:

```jsx
import { Card, CardContent } from "@/components/ui/card";
import { Button } from "@/components/ui/button";

<Card>
  <CardContent className="p-4 gap-3 flex flex-col">
    <img src={product.image} className="rounded-md" />
    <p className="font-medium text-foreground">{product.name}</p>
    <p className="text-muted-foreground">{product.price}</p>
    <Button>Thêm vào giỏ</Button>
  </CardContent>
</Card>
```

Xong trong 5 phút, nhất quán với toàn bộ app vì dùng chung token (`text-foreground`, `text-muted-foreground`, `rounded-md`).

<Callout title="Cẩn thận">
Bẫy phổ biến nhất: bạn "implement xong" nhưng lại tạo ra một mớ class ngẫu nhiên và hardcode màu riêng, thay vì dùng token và component của design system. Ba tháng sau, app của bạn có 4 kiểu card khác nhau mà không ai nhận ra. Mỗi khi implement, hỏi: "Có component/token nào đã có chưa trước khi tôi viết cái mới?"
</Callout>

<Callout title="Nhớ nhé">
Design to code tốt = dùng component + token sẵn có, không phải copy pixel. Mục tiêu là speed + consistency, không phải sao chép chính xác từng pixel từ Figma.
</Callout>
