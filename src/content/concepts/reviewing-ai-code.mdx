Hãy hình dung bạn nhận một bản dịch từ cộng tác viên giỏi nhưng đôi khi tự bịa từ chuyên ngành nghe rất đúng. Nếu bạn chỉ đọc lướt xem "có vẻ trơn tru không", bạn sẽ bỏ qua những chỗ họ tự chế. Với code AI cũng vậy — vấn đề không phải code *có vẻ đúng*, mà là bạn cần cách đọc khác đi để bắt chỗ AI **bịa**.

## Là gì

Review code do AI sinh là quá trình kiểm tra *có chủ đích* nhắm vào các lỗi đặc trưng của AI — khác với review code người viết thông thường. Lỗi nguy hiểm nhất: **hallucinated API** — agent gọi hàm hoặc import package không tồn tại, đôi khi package nghe-có-vẻ-thật nhưng thực ra là giả mạo độc hại (typosquatting).

## Ví dụ thật

Agent thêm dòng `from stripe import create_payment_intent` — nhìn đúng hoàn toàn. Nhưng API thật của Stripe là `stripe.PaymentIntent.create(...)`. Nếu bạn không verify, lỗi chỉ xuất hiện lúc chạy production, không phải khi đọc code.

Ngoài hallucinated API, bốn điểm review đặc trưng khác:

1. **Test có thật sự fail không?** — Chạy thử xem test có bắt được lỗi thực nếu tính năng hỏng không, hay test luôn pass bất kể kết quả.
2. **Abstraction thừa** — Agent thường thêm lớp interface, class wrapper "phòng xa" cho trường hợp không bao giờ xảy ra. Hỏi: *cái này giải quyết vấn đề gì ngay bây giờ?*
3. **Scope creep âm thầm** — Agent tự đổi file ngoài yêu cầu, tự thêm import, tự "tiện tay refactor". Từ chối mọi thay đổi không nằm trong task.
4. **Reviewer subagent ở context mới** — Dùng một phiên Claude mới (không có context của phiên viết code) để review. Reviewer không bị bias bởi lý do tại sao code được viết vậy.

<Callout title="Cẩn thận">
Đừng review bằng cách hỏi agent đã viết code: "code này đúng không?" — nó sẽ tự xác nhận. Reviewer phải là context mới, hoặc chính bạn với checklist, không phải phiên đang viết.
</Callout>

<Callout title="Nhớ nhé">
Code AI đọc trơn tru ≠ đúng. Verify từng import, từng API call — đừng tin "nhìn đúng".
</Callout>
