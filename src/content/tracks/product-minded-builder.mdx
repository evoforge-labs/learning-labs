# Product-minded Builder

Lộ trình rèn tư duy sản phẩm cho người làm kỹ thuật: phân biệt problem vs feature, đào nỗi đau người dùng, cắt scope thành MVP, đo outcome và ra quyết định dưới constraint.

## Outcome

Sau track này, bạn chuyển từ:

> Tôi build đúng task.

sang:

> Tôi dùng kỹ thuật để tạo kết quả có giá trị cho user và business.

## Track này luyện gì?

- Tách request khỏi problem thật.
- Hỏi câu hỏi tốt trước khi code.
- Cắt scope thành MVP hoặc experiment nhỏ.
- Chọn metric để biết có hiệu quả không.
- Đánh đổi giữa speed, quality, debt và learning.
- Ship để học, không ship cho có feature.
- Làm solo dev nhưng không trốn trong code.

## 30-day curriculum

### Week 1: Stop jumping to solution

1. Problem vs Feature
2. User Request vs User Pain
3. Good Discovery Questions
4. Evidence vs Assumption
5. Success Metric vs Output Metric

### Week 2: Scope and validate

6. MVP Scope
7. Manual Before Automation
8. Trade-off Under Constraints
9. Post-launch Learning
10. Mini Case: App Chậm

### Week 3: Metrics and feedback loops

11. Activation and Time-to-Value
12. Leading vs Lagging Metrics
13. Guardrail Metrics
14. Read Fake Launch Data
15. Write Post-launch Review

### Week 4: Solo builder operating system

16. Weekly Planning: build / sell / support / learn
17. Tech Debt Decision
18. Customer Support as Discovery
19. Roadmap 4 tuần
20. Kill / Keep / Iterate Decision

Days 21-30 nên là real-world simulation và project application.

## Learning progression

Mấy ngày đầu dùng ABCD / select-many / classification để luyện nhận diện pattern. Sau đó tăng dần sang short answer, mini case và simulation.

## First principle

Bớt yêu solution. Yêu problem nhiều hơn.
