## Tình huống

Bạn vừa nhận được spec từ khách hàng:

> "Chúng tôi cần một app tóm tắt tài liệu nội bộ cho khoảng 5.000 nhân viên. Mỗi người dùng upload tài liệu PDF (dài 20–50 trang, viết bằng tiếng Việt), nhận bản tóm tắt 300–500 từ. Ước tính 2–3 request mỗi người mỗi ngày."

Trước khi viết một dòng code, bạn cần trả lời 3 câu hỏi.

---

## Task 1 — Chọn model phù hợp

Đọc lại [concept-foundation-model](/concepts/foundation-model) và [concept-reasoning-models](/concepts/reasoning-models).

**Hãy quyết định và giải thích:**

1. **Standard hay reasoning model?** Tóm tắt tài liệu là tác vụ sáng tạo/phân tích nhiều bước hay extraction/summarization thẳng? Model nào phù hợp hơn?

2. **Tier nào?** Giữa Claude Opus 4.8 ($5/MTok input), Sonnet 4.6 ($3/MTok input), và Haiku 4.5 ($1/MTok input) — bắt đầu với model nào? Căn cứ vào đâu?

3. **Cần multimodal không?** PDF 50 trang tiếng Việt — bạn cần model nhận image hay text đã extract?

<Callout title="Mẹo">
Bắt đầu với model rẻ hơn, đo chất lượng, leo lên model đắt hơn chỉ khi cần. Đừng default Opus vì "an toàn" — chi phí sẽ giết bạn ở scale 5.000 user.
</Callout>

---

## Task 2 — Ước lượng token và chi phí

Đọc lại [concept-tokens-tokenization](/concepts/tokens-tokenization).

**Một request điển hình:**
- PDF 30 trang tiếng Việt ≈ 7.500 từ tiếng Việt ≈ bao nhiêu token? (dùng quy đổi từ concept)
- System prompt + instruction ≈ 500 token
- Output (tóm tắt 400 từ tiếng Việt) ≈ bao nhiêu token?

**Tính toán:**

1. Ước lượng **input token / request** và **output token / request**
2. Ước lượng **tổng token/ngày** với 5.000 user × 2.5 request trung bình
3. Tính **chi phí/tháng** với model bạn chọn ở Task 1 (dùng giá thật từ concept)

**Trình bày kết quả dưới dạng:**

```
Input/request:  ______ token
Output/request: ______ token
Request/ngày:   ______
Token/ngày:     ______ input + ______ output
Chi phí/tháng:  $______
```

## Task 3 — Quyết định thiết kế bị ảnh hưởng bởi context window

Đọc lại [concept-context-window](/concepts/context-window).

**Kịch bản phức tạp hơn:** Khách hàng muốn thêm tính năng: user có thể hỏi tiếp về tài liệu sau khi xem tóm tắt (chat Q&A).

Chỉ ra **một quyết định thiết kế cụ thể** bị ảnh hưởng bởi context window:

- Bạn có đẩy toàn bộ nội dung PDF gốc vào context cho mỗi câu hỏi không?
- Nếu user hỏi 20 câu liên tiếp, context tích lũy thế nào?
- Bạn xử lý vấn đề "context rot" bằng cách nào?

**Trả lời ngắn gọn:** Mô tả quyết định thiết kế, lý do kỹ thuật, và trade-off.

---

<Callout title="Cẩn thận">
Không có đáp án duy nhất đúng. Bài này đánh giá **lý luận** của bạn — bạn có nhận ra trade-off không, có căn cứ số liệu không, có thấy được hệ quả kỹ thuật không.
</Callout>
